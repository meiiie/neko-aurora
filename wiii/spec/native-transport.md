# Wiii local native transport

This additive candidate extends the byte-bound restored Wiii source and the existing Neko Bot bridge at `1682909182cfe5c5d11629dd093cbd704a6f2c37`. Native and pre-existing service inputs were restored unchanged in thin-repository baselines `1107dd097ef7e12f46acd4d14a5943ea04c18532` and `da654879f55e9ccb71c79e48e7526833ede34053`. The production delta is measured from the latter baseline; these restoration commits are not a claim that the old Wiii application was tested again.

## Neko Bot connection

`LocalBotBridge` starts disconnected. Mounting the project connection panel invokes only native status. A user enters a literal local port and chooses Connect. The main local WebView command opens an owner confirmation dialog before any HTTP request. Decline, dialog failure, stale approval or disconnect fail closed. There is no renderer argument for approval, token, cookie, owner, space, URL, headers or grants. This slice does not connect to a user's running service while the user is away.

After approval, Rust performs an exact `http://127.0.0.1:port/` bootstrap without proxies or redirects. It accepts one correctly scoped HttpOnly, SameSite=Strict Neko session cookie. The cookie is an in-memory Rust field only, not serializable, persisted, logged or returned to JavaScript. The authenticated metadata catalog determines owner, space, channels, membership and revisions. Catalog version 1 is pinned to immutable Neko Bot server `28ae91010235bc287876922d3d0daa1927f8e005`.

The user explicitly selects a shared channel. A native link records its exact catalog revision and server owner/space; it makes no registration or message HTTP request. Nonsecret source-session/thread identities are durably keyed by owner, space, Wiii project and channel. The project ID is provenance, not permission to read a Neko project. Opening the existing bridge panel uses this native lease and the existing durable outbox/cursor logic. Neither restored handoff payloads nor client source IDs supply runtime, account, file or workspace authority.

The native request allowlist is registration POST, messages POST and replies GET with a numeric cursor. Each route and body is checked before HTTP. Registration and replay must match the full source/session/thread/channel/revision/owner/space binding; an unknown saved adapter is verified through the server before native message intake. Owner or binding drift fails closed; channel-revision conflicts are not automatically rebound. Disconnect invalidates local leases and late responses, and discards the cookie; it does not cancel already committed server tasks. Reconnecting requires another explicit owner confirmation, retains the durable original source identity, nonce and cursor, and verifies the new server binding.

Native ACK projection returns correlation and publication metadata, not the server's model-context pin or unrelated private history. Replies use the existing 1 MiB hostile-page bound, stable cumulative reply IDs and sequence/cursor fences. The separate bridge panel does not export replies into ACP/model context. File/resource selections remain subject to the server's source-reader and publication checks; this UI does not create grants or select file content on its own.

The five Neko commands and two service commands are main-window capabilities. Runtime checks restrict their caller to the main local packaged WebView, with localhost:1420 allowed only in a debug build. Tests exercise the URL/capability decision and the actual Rust request manager. They do not attest the OS identity of a loopback service or prove a native dialog was clicked by a human.

## Existing Wiii service compatibility

Restored Wiii actively used the generic HTTP plugin for adaptive local service requests, refresh/logout and login health checks. Its original wildcard loopback capability and redirect-following transport could bypass the Neko native route guard. The candidate removes the generic HTTP plugin registration and the two renderer HTTP loopback allow rules, and removes HTTP loopback from `connect-src`. The crate remains a dependency solely for its already cached reqwest re-export; Cargo and npm lockfiles are unchanged.

Existing callers use `wiiiServiceFetch`, backed by `neko_wiii_service_fetch` and `neko_wiii_service_cancel` plus a Tauri Channel. Its only origins are literal configured localhost/127.0.0.1 ports (normalized to 127.0.0.1) and exactly `https://wiii.holilihu.online`. Routes are exact `/health` or `/api/v1/**`; encoded or dot path traversal, fragments, userinfo, arbitrary URLs, Neko `/` and `/v1` routes, redirects and proxies are denied. It preserves multipart boundaries, binary request/response bytes, progressive SSE, null-body status responses, AbortSignal and reader cancellation. Header deadlines retain the existing 1–900 second range; SSE body reads continue until EOF/cancel or the response bound.

Safe percent-encoded Unicode and colon IDs used by existing API helpers remain valid. Each path segment is decoded once and rejects decoded separators, dot segments, percent signs, controls, question/hash delimiters and invalid UTF-8/escapes. Raw and serialized paths must retain the same validated route; the native URL serializer must preserve the exact encoded path. An owned HTTP fixture verifies the actual request line for a colon/Unicode connection ID. This parity delta follows immutable `c9fc006` without changing its earlier review or receipts.

An independent review of `c9fc006` identified that generic opaque IDs admitted `.`/`..` as adapter URL segments. The additive delta rejects these route-specific IDs before HTTP and rejects such registration receipts, while preserving opaque source IDs as provenance. Native request construction also checks the serialized path and query before adding the cookie, so URL normalization cannot silently change an allowed route. The original review probe and corrected zero-extra-request fixture remain separate evidence.

Request and response bodies are bounded at 64 MiB, matching the existing 20 MiB document and 50 MiB organization-upload flows with framing headroom. Request headers are limited to Authorization, X-API-Key, X-User-ID, X-Organization-ID, X-Session-ID, X-Request-ID, Content-Type, Accept and Accept-Language. These remain scoped to the existing Wiii service route and are never used by Neko bridge authentication. Response headers are limited to content type/length/disposition, cache-control, etag and request/trace IDs. Cookies and Set-Cookie are neither accepted nor published, and no cookie jar is enabled. The transport does not persist any authentication header.

At most 32 service requests are active. Cancellation before native admission is tracked with at most 256 pending IDs. Exhausting that bound fails closed for later admissions until the process restarts instead of silently losing cancellation. Normal queued cancellations are consumed when their matching fetch reaches admission. Client-generated IDs are fresh for each request. Cancelling one admitted SSE request closes its HTTP stream without aborting a different request.

External HTTPS behavior, ws/wss loopbacks and the existing computer viewer remain separate inherited authority. In particular `frame-src http://127.0.0.1:*` and top-level navigation are preserved because the restored computer viewer uses them. This candidate does not claim whole-application zero-HTTP access or globally prevent every possible loopback bootstrap. Root may add a separate server-side Fetch Metadata guard without changing this scoped transport contract.

## Validation and remaining gates

Commands are recorded with full source hashes, tool versions, environment, deadlines, generated-schema hashes and PASS/FAIL/BLOCKED in the sealed receipts. All Cargo commands use existing offline dependencies, the unchanged Cargo lock, existing MSVC and the approved E target/temp. No system installation, provider, cloud, production auth, user journal, native window or dependency download is part of these gates.

The scoped gates are:

- `cargo check --offline --locked` for the full materialized native crate.
- `cargo test --offline --locked --lib neko::local_ -- --test-threads=1` for connection/source/receipt/route/cookie/redirect/cancellation/bounds and inherited-capability migration.
- The separately enabled `actual_owned_go_catalog_registration_intake_replay_and_disconnect` test against a fresh, own-built Go28 binary and journal. Owner confirmation is synthetic inside the test, never a renderer argument or GUI click.
- Unchanged bridge tests plus native-client and service-stream tests under Bun; strict TypeScript checks for pure transport modules; browser-target bundling with external packages only checks syntax/module traversal, not a full production React build.
- Headless Chrome with the exact candidate CSP and two owned loopback origins: generic fetch to bootstrap/catalog is blocked with zero protected-server requests while same-origin fetch succeeds.

The earlier Rust fixture failure is retained: a Windows accepted socket inherited nonblocking mode, producing WouldBlock and a second panic in fixture cleanup. Explicit fixture blocking mode and non-panicking cleanup fixed the harness without changing production timeouts or security. Its negative source/log/binary hashes remain separate from corrected receipts. The prior disk-full native failure, prior successful frontend build and prior four generated-schema differences also remain preserved.

The exact `ab6923b` offline inventory initially found 752 of 910 locked package versions absent after the earlier disk-relief cleanup. That receipt is preserved. Root then explicitly authorized public npm packages pinned by the unchanged archived lock, in a new E-only source/cache/temp directory with empty task npmrc and lifecycle install scripts disabled. Preparation installed 844 packages. The whole React frontend passed `tsc` 5.9.3 and Vite 8.0.10 production build; the old 525-file dist remains unchanged. Installed versions and cached tarball integrity are recorded separately from source validation.

The new native shell also passed `cargo build --offline --locked --features tauri/custom-protocol`, embedding the current production frontend through the existing dependency feature. Its version-named executable was copied and hash-verified without being launched. Original and compiler-generated schema hashes remain separate artifacts. Five actual React component tests under pinned React 18/Vitest/jsdom exercise disconnected mounting, status-only native mounting, denied connect, explicit channel selection and late connection ACK after project navigation; IPC is injected and any HTTP throws.

Actual native WebView mounting, human owner confirmation, IPC Channel delivery/AbortSignal under WebView, current UI/pixel acceptance, user service pairing, physical phone/AT, real providers and cloud remain pending. The GUI slot is held by Root, so this slice supplies a compiled candidate and fixture evidence without opening a native window. A local compile, jsdom mounting and authenticated fixture wire are not those acceptance results.

For rollback, stop the candidate or disconnect to discard the volatile cookie and invalidate leases; server-committed jobs continue. Preserve durable original source identity, nonce and cursor. Review the authority downgrade before reverting the source branch; do not silently restore generic loopback HTTP capabilities. No production user state, service credential, grant or provider configuration was changed.
