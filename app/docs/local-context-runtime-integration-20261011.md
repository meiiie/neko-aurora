# Local context admission integration

Candidate integration builds on Root27aff09, the pure Go manifest fb4187f,
the pure Rust validator3cbf4b5 and Core9f2303f. The promoted primary28ae910
and its older Core fa48 remain unchanged until native combined gates pass.

Trusted manager configuration opts into context protocol1 only for a pinned
Core that advertises this protocol. New local authenticated message intake,
linked supplement/replace intake and generated collaboration stages save the
private manifest and canonical digest before journal commit. No renderer can
supply an original sender, manifest or native source ID. Queued never-launched
historical work can adopt the protocol in a typed claim; an explicit fresh
context action can also adopt it. Previously launched context0 sessions never
silently change Core or context protocol.

Original-user provenance belongs to the durable owner message. For a group it
belongs to the authenticated collaboration.created ID and literal goal;
generated stage instructions are derived sources. Pinned bot identity is a
derived source. Prior task inputs have unresolved original authorship, and
continuity retains literal dates/entities and the owner's recorded admission
revisions. File content still requires the exact live trusted reader pin;
metadata references create no read grant. Full original text is preserved;
text longer than8192 UTF-8 bytes uses an explicit prefix span with its full
extent and digest. The whole encoded host frame must fit64000 bytes before
intake commit and lease issuance. Private manifests are stripped from public
snapshot, SSE, command receipts and other public work projections.

Rust validates the manifest before task state creation/Core launch, requires
the fresh prompt to equal the literal primary text, negotiates the Core
protocol and validates the native seven-field admission receipt. Its one
source ID is an opaque64-hex Core journal group hash, not a file/message ID.
Go saves that receipt with current task/execution/process/lease provenance.
Resume supplies the prior receipt and rotates only the activation/attempt;
the session, manifest, pin and native source hash remain unchanged.

Core MCP tools/call sends only neko.operation. The trusted Rust bridge first
validates that operation against the admitted task, rejects extra operation
metadata, then attaches its verified context receipt for the Go broker.
This receipt never comes from model arguments. An exact selected file range
may receive neko.contextSource metadata bound to the actual operation; other
authorized reads remain ordinary descriptive tool output. ACP updates and
prompt results must echo the saved current context receipt. Artifact and
publication fences remain unchanged.
