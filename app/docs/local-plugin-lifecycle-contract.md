# Local plugin lifecycle and trusted tool broker

Source baseline: immutable Root `931c4b76eb82bc92b1ca2c80a89ab04112c0d5db`. This slice implements the local portion of direction section 3.5 and SCN-PB-008/016/017. Neko Core remains the only semantic loop. No provider, external plugin transport, installation, authorization popup, credential retrieval, or grant is implemented here.

`POST /v1/plugin-lifecycle` accepts version 1, id, action, required expectedRevision, clientNonce and optional manifest. Actions are import/update/disable/remove; enable is supported only for original host built-ins. A journal event atomically commits the versioned policy. A duplicate nonce with the same body returns the current descriptor; a changed body conflicts. Tombstones and nonce receipts persist across restart. The bounded catalog retains at most 18 materialized records and 2048 lifecycle commands; capacity exhaustion fails before commit.

`GET /v1/plugin-catalog` and snapshot.plugins expose the ledger authority catalog. This coexists with the earlier `/v1/plugins` connections descriptor catalog, which remains unchanged and disabled. That older catalog does not confer execution authority. External lifecycle manifests always report `manifest_only_disabled`; they cannot supply publisher, executable, location, authentication, endpoint, or transport fields. Schema/tool descriptions are descriptive data. A name matching a built-in never binds its implementation.

The only trusted registry entries are `neko-artifacts` / `artifact.write_text` and `neko-project-sources` / `project.read_file`. Publisher, version, schema, and implementation come from server constants. The project reader additionally requires an immutable source already selected for the task; stage 1 and 2 of a collaboration never write artifacts. This module does not grant a new file scope or turn a user's generic request into permission to use an external service.

Message intake optionally accepts pluginSelection as an array of `{id,expectedRevision}`. Omission chooses currently available eligible built-ins. An explicit empty array is tool-free. New Work has toolPolicyVersion 1 and immutable pluginPins containing the tool, plugin revision, publisher, version, and canonical schema hash. A pointer selection preserves the distinction through JSON even when pins are empty. Context pins include this policy in their existing SHA-256 before the shared encoded 64000-byte prompt check. Lost-ACK message retries compare the original selection; they never choose a newer revision.

Selected project files also supply inline excerpts to the runtime prompt. Such ingestion requires a live trusted project reader pin even when no MCP read occurs. Selecting files with an explicit empty/omitted reader policy, or while the reader is disabled, conflicts before commit. A context refresh keeps the exact own policy and checks it before recapture. Historical source references are recursively fenced by the original source's reader pin. Later continuity/admission modules must preserve these checks when exporting actual file spans; a literal reference identifier alone is metadata, not source ingestion.

Historical toolPolicyVersion 0 is an immutable implicit revision-0 policy for the original eligible built-ins. It is not upgraded during replay. The first disable/update/remove fences it, and enable at a later revision never revives it.

Catalog mutation and dispatch/read/effect/output run under the ledger mutex. Current exact pins are rechecked by the existing context and account gates before claim, launch, admission, capabilities, tool execution, text, completion, requeue, and adapter publication. Recursive context ancestry also rechecks source plugin pins. A durable catalog change immediately denies late output even if a crash occurs before suspension events. Existing recovery reconciles suspended tasks and artifact receipts without treating task-local revocation as journal corruption. Existing durable effects retain receipts; revocation does not undo them or repeat unknown outcomes.

Task supplement/replacement copies the parent's exact plugin policy. Collaboration creation freezes its policy once, and every stage carries that policy. Neither flow silently selects a newer plugin revision. Plugin revocation suspends a group before another stage. Resume/context refresh cannot repair a revoked task's own tool pin; create a new request with an explicit current selection. A tool-free dependent task may explicitly refresh its context after existing stopped/operation gates pass, excluding revoked ancestors.

Validation history and exact source/artifact hashes are recorded in the handoff manifest under the owned `.build` directory. Ledger tests use synthetic Core bindings and stopped receipts; those are not native process-wait proof. Browser/UI, physical phone, external install/auth, cloud, multi-owner permission, and real model evaluation remain separate acceptance gates.
