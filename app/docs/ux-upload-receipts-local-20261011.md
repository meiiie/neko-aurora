Before upload POST, a bounded Web Locks/localStorage marker records only original project/channel/revision/nonce, filename, SHA256 and byte length plus the observed channel revision and a canonical marker digest. At most four markers and 8KiB are admitted. File bytes/base64/excerpts/keys are never persisted. Denied storage, malformed/extra-field/changed-digest records fail closed before POST. A marker digest detects invalid metadata, not a grant or server receipt.

Reload performs only receipt GET and fresh public-file reconciliation. A committed upload retires the original marker, even after project rename or file-access withdrawal; that acceptance does not regrant the file. Unknown receipt requires explicit same-file selection and submit. Filename, SHA256 and length must all match before the original canonical wire body/nonce/revision is retried. A recheck just reads the original receipt. Scope/revision removal blocks retry, preserving the original marker until explicit retirement.
