# Connections and account-scoped private input

The user's supplied reference was viewed as actual pixels. Its private input card has a title, action scope, one input with a save button, and a privacy footer. Static Grok safe-input and account-detail chunks were read as UX references only. No bundle was executed and no proprietary code/assets were copied.

Two designs were compared before implementation. A dialog-only catalog/editor has less interaction surface but does not preserve the reference's inline action. The chosen design retains the account dialog and adds a temporary inline card for an existing account's explicit “Nhập bí mật” or “Đổi bí mật” action. It does not invent a task credential request, OAuth consent, a Computer pane or a vault execution grant. The approved light layout remains. The derived brand glyphs retain their original paths with an added space before Bot; identifiers and storage paths are unchanged.

An account operation contains public typed metadata, the exact ID/revision/nonce, the Go-compatible input fingerprint, the original view/account selection and a state of draft, sending, unknown, confirmed or stale. The password value exists only in its form field and the local POST serialization path. It is cleared when the request begins. It is not retained for retry, placed in chat/outbox/localStorage, returned in public receipts or captured in screenshots. The parser and fingerprint comparison protect route/body identity, including Go sorted-key JSON and HTML escaping.

Editing keeps provider and endpoint immutable. A blank secret preserves the Rust DPAPI vault reference/generation. A nonblank secret rotates only that exact account. Metadata and UI consistently describe `stored_unverified`; a successful local save does not establish provider readiness or grant execution authority.

An uncertain ACK exposes read-only receipt reconciliation. Found/current receipts verify the original fingerprint and account metadata. Used/retired receipts cannot replay. Unknown/unused requests permit explicit retry with the same public shape, account revision and nonce, after the user re-enters the original secret when needed. There is no automatic POST, new nonce or persisted secret. These account operations are page-lifetime memory; reload reads the committed catalog and does not reconstruct pending private input.

Closing, Escape, provider/action/account-selection/navigation changes and catalog revision changes clear private fields. The native dialog's queued close event cannot clear a newly opened inline action. Disabled controls move keyboard focus to the scoped Cancel/Back control. Late ACKs cannot clear the next action's password field, move its focus or change navigation. Existing tasks, aliases and channel histories remain bound to their original account pins.

Pstack was adapted to the native tool environment. Model the Domain chose the account-operation state machine. Separate Before Serializing Shared State kept the private action and isolated E fixtures separate from Root's Go/Git ownership. Prove It Works required actual Go, Chrome, Rust DPAPI, receipt and disk checks. The prescribed Grok/Claude arena models were unavailable; no multi-model arena is claimed. Root accepted design B before implementation.
