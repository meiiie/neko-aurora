# Local principal/device candidate

This candidate adds default-off, explicitly configured loopback fixture identities. It does not implement production login, device pairing, OAuth, remote authorization, or provider grants. The ordinary local-owner application retains its existing session route and cache keys.

The browser reads authoritative `/v1/session` metadata before loading selection, outbox, or command caches. Fixture cache namespaces bind authority, space, and actor. Every request captures a session generation; actor/session changes abort old requests, close their event stream, clear private in-memory views, and prevent late acknowledgements, digest computations, and `finally` blocks from importing data or releasing another actor's nonce. The `X-Neko-Session-Binding` header is an original-intent precondition; the server still authenticates the cookie and authorizes current audience membership.

Fixture messages are never automatically replayed, including after a reload. Their original body and nonce are retained in the original actor namespace. A local-only `originSessionBinding` records which session prepared a message. Missing or changed binding prompts explicit review; it is excluded from the POST body and server payload identity. Reader or removed-channel views cannot issue retry. This does not grant an expired request or replace its pinned requester.

Shared transcript human names come from the trusted requester actor, with `Bạn` reserved for the currently verified actor. The scoped runtime projection does not claim that execution is unavailable: each request shows its own progress. Scoped event frames and cursors bind the current session. A generic scope-invalidated event clears private content before resnapshotting, including when the caller has lost membership.

The Go journal, Rust host, and Core manifest-v2 preserve the truthful requester independently of the workspace owner. Historical manifest-v1 owner receipts remain historical receipts. Completed shared history and files can remain readable by current audience members after the submitting device expires; that visibility never grants new execution. Current device/session revocation suspends active execution through the native stop-proof path and retains the original requester and receipt fences.
