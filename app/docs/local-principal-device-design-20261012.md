# Local fixture principals and devices

Baseline: application/delivery `79a3c018656fc4bea61a06bcfac9488f9c3596ea`, Core `5ad10a432b738bc26d53c6686c13994fcc5677b3`. This is a bounded, default-off loopback fixture slice. It does not provide production login, OAuth, pairing, remote transport, real device keys, or external access grants.

The server resolves an immutable verified principal from an opaque, server-issued session. Client actor IDs are never identity proof. Explicit fixture bootstrap tickets select preconfigured fixture actor/device records. The fixture mode never mints the legacy owner cookie from GET `/`, never falls back to that cookie, and refuses a non-loopback listener before opening state. Session tokens and tickets stay outside source, reports and snapshots. Rotation, device revocation, expiry and service boot epoch invalidate execution and old streams/cursors.

Workspace ownership remains `local-owner` / `local-space`. A versioned fixture human ACL on a shared channel distinguishes actors from recipient bots. Changing its members advances the existing audience revision. Private lanes and owner accounts, profiles, plugin controls, raw runtime state, and adapter administration remain owner-only. Member responses contain only authorized shared messages, status, attribution and public file/report descriptors; context excerpts, account pins, filesystem bindings and leases do not cross that boundary.

Each new verified intake records a requester pin. Its version-1 shape is `actorId`, `spaceId`, `authorityId`, `deviceId`, `deviceRevision`, `sessionId`, `sessionRevision`, `issuerEpoch`, and `expiresAtUnixMs`, plus `version`. IDs use the existing manifest ID grammar; all counters and time values are positive safe integers. The session pin is attested by the trusted intake, not supplied as client JSON. Active intake, claim, tool read and completion require the pin's current authority. Completed shared history does not expire just because its submitting session expires. Existing source/audience/plugin fences still apply.

ContextManifest version 2 contains the six existing keys plus `requester`. Its primary sender equals requester.actorId and requester.spaceId equals scope.spaceId. Version 1 retains owner-only equality and rejects an extra requester. Scope ownership is never rewritten to impersonate a participant. Go, the Rust host and Neko Core validate the same shape and manifest digest. The requester describes trusted provenance; it does not grant tools or turn retrieved text into authority. Existing context protocol, admission and launch envelopes remain version 1.

Local idempotency distinguishes actor, space and authority while retaining the same exact command nonce across that actor's devices. Duplicate receipt retrieval cannot refresh the original pin, grant, content or audience. Two actors using the same nonce remain separate. Session rotation requires a fresh snapshot/cursor and keeps that actor's existing pending intent; revocation never silently creates another request. This is local journal idempotency, not proof of external exactly-once effects.

Every scoped read, send and stream frame checks current actor membership. The scoped transport cursor binds journal, actor, authority, device, session and audience. It cannot reconnect under another actor or session. Browser outbox, selected view and durable control journals are actor-namespaced, loaded only after authoritative session metadata. A generation fence prevents an old ACK or stream from writing into a new actor's view. Existing owner data remains preserved under its legacy key.

The initial multi-human surface is shared plain-message intake, authorized channel history/snapshot/events/local-sync and public report/file reads. Nonowner group creation, task controls, project changes, account/plugin/adapter configuration and publishing private bot history are denied until separately implemented. The two existing bots and approved light design remain. Connections displays concise fixture session status without a new account framework.

Acceptance uses isolated Alice (`local-owner`), Bob (shared reader/writer), and Eve (outsider) sessions on loopback. Significant checks cover identity spoofing, private data rejection, ACL changes, active revoke with authentic process-stop evidence, session rotation, actor-scoped duplicate ACK, cross-actor/cross-session cursors, browser namespace isolation and honest primary-sender admission. Existing archives, dirty user files, previous release packets and binaries are hash-protected. Each checkpoint is secret-scanned, and exact code/build identity accompanies evidence. Native phone, AT speech, real provider/model quality, Wiii ownership UI and remote cloud/device acceptance remain separate gates.
