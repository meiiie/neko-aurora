## Context behavior that passes

- Missing capabilities hides actions and dispatches no context request. Access-only capability exposes a named pressed toggle; missing access metadata defaults to revision 0/granted true.
- Context controls reach the 44x44 product goal at ordinary mobile widths and at **844x390, coarse pointer, 5 simulated touch points**. Ordinary 320/390/700 width cases have no horizontal document/panel overflow. The short-height clipping finding is independent of target dimensions.
- Refresh is shown for matching native PID/session stop proof or never-launched work, and hidden for PID mismatch, session mismatch, missing/incorrect receipt, not stopped, unknown WSL proof, pending operations, attempt limit, revoked source access, suspending state, wrong desired state, unsafe epoch and absent refresh capability. These are UI gates over fixture data, not verified process-stop evidence.
- Context controls remain inside the mobile Tab/Shift+Tab scope; Escape closes and returns to the work opener.
- Pending access prevents duplicate dispatch and does not optimistically change granted state. Its status region is exposed in the AX tree. Access 503 retry retains the exact request body/nonce. HTTP 409 obtains a fresh snapshot and performs no automatic access retry.
- A late access ACK preserves the newly selected bot, draft and composer focus. An ordinary older ACK with equal access revision cannot replace newer SSE epoch/context state. The mixed-vector counterexamples above remain distinct.
- Regrant leaves suspended work suspended and does not invoke refresh. Explicit refresh sends only request ID and expected epoch; pending clicks do not duplicate it. An uncertain refresh ACK resyncs the fixture snapshot and does not replay refresh automatically.
- Removing capabilities during a pending ACK hides actions and blocks hidden dispatch. A late refresh ACK after closing the panel preserves the continuing draft/focus and does not reopen the dialog.
