- [ ] Tab and Shift+Tab around each mobile overlay; Escape, explicit close, backdrop and OS/browser Back. Close the topmost transient UI before navigating away where the product promises that behavior. Background work persists; dismissing a submitted form does not promise server rollback.

## Multiple-client/device contract and remaining gates

The actual local Go test establishes these expectations for **two clients sharing one local journal**:

| Scenario | Expected / observed local result |
|---|---|
| Concurrent retry, same source bot + clientNonce + original payload | One request identity; one 201 and one duplicate 200. |
| Same source bot + nonce, changed text/lane | Conflict 409; never overwrite the existing goal. |
| Independently authored same text with different nonces | Separate requests. Text equality is not a global deduplication key. |
| Same nonce on a different bot | Independent identity within bot scope. |
| Reconnect with Last-Event-ID | Return the next committed sequence; repeat deliveries must not create new UI rows. |
| Ahead-of-journal cursor | Reject 409; client needs authoritative snapshot recovery. |
| Hard kill/restart after ACK | Same snapshot and request identity; retry is a duplicate, not a new obligation. |
| Cancel one request | Other foreground/background requests retain their identity and status. |

Client fixture tests additionally check stale/duplicate SSE ignores, gapped sequence resnapshot, retry nonce preservation, and ACK/snapshot/event outbox reconciliation. They do not establish server fsync or tool-effect semantics.

Physical separate devices need their own authenticated owner/space/bot/session transport, explicit nonce provenance for retransmitting the same logical request, authorization and revocation behavior, session expiration, device-local outbox ownership, artifact access and clock/sequence recovery. Different devices independently creating messages should use independent nonces. Browser outbox data is local to one origin/profile; it is not a device-sync queue. Shared-origin tabs also need storage/race testing because in-memory outbox copies can diverge; local journal dedup is a defense, not proof of coherent cache behavior. None of these cloud/device acceptance claims were made.

## Primary criteria

- [W3C WCAG 2.2 SC 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html): distinguish the AA 24×24/spacing criteria from Neko's more generous 44×44 product goal.
- [W3C APG modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/): focus enters a named modal, stays inside its keyboard scope, Escape dismisses and focus returns logically. APG is implementation guidance, not evidence of tested AT behavior.
- [W3C WCAG SC 4.1.3](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html): meaningful status updates need programmatic exposure without requiring focus relocation.
- [MDN VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport): visual and layout viewport changes are distinct; keyboard-sized desktop layout emulation does not establish the OS keyboard behavior.

No WCAG conformance certification, real-phone acceptance, native Tauri visual acceptance, real-provider evaluation or cloud sync is asserted by this review.
