# Local offline backup and restore dry-run

Requested from delivery3977042/applicationfb48e1 after prior data loss. Scope is a consistent local snapshot, checksum verification and restore into a new isolated directory. Production state and all old copies remain unchanged. No upload, credential/grant creation, plaintext secret export, automatic job restart or destructive restore.

The existing Go CLI will gain mutually exclusive offline create/verify/restore-dry-run modes. Backup requires the stopped-service writer lock, strict read-only journal replay (no torn-tail repair or identity creation), no live recorded Core process, pinned single-link regular files and unchanged inventories. Persistent ledger, artifact/upload bytes, encrypted account vault, executor state including executor-v1.lock identity, native receipts and task checkpoints are included; only root writer.lock is omitted. Unsupported paths, pending temporary writes and quotas fail rather than silently omit data.

Every payload is protected with current-user Windows DPAPI, non-interactive and without machine-wide protection. Entropy binds the snapshot header and each file's relative path, bytes, modification time and hash. The detailed file manifest, including private names/paths/checksums/sizes, is also DPAPI-protected. The public manifest is a bounded envelope containing only snapshot ID, protection type and encrypted-manifest size/hash. It has an exact checksum and strict bounded schema; ciphertext has its own checksums. No plaintext staging files or decrypting existing account credentials. Same Windows user/machine restore is the local acceptance scope; this is not cross-device/offsite disaster recovery. Reference: https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata .

Restore validates all protected bytes first, requires a nonexistent destination outside source/backup, creates it atomically with a protected inheritable current-user-only Windows DACL (no existing ACL changes), and places a permanent read-only marker before any payload. Copied journal and files retain bytes/modification times and receive read-only file attributes; this also makes older binary journal write-open fail. Strict semantic replay validates sequence and identities without Core/runtime/recovery. Marker blocks journal mutations, all non-GET HTTP calls before catalog/vault actions, and runtime.New/configured launch before creation/admission/reconciliation. There is no enable/remove-marker API. A failed target stays marked and is not reused or deleted automatically.

Quotas: 5,000 files, 64 MiB per file, 512 MiB total, 2 MiB manifest; regular ASCII state paths only, no traversal/ADS/reparse/hardlinks. Failures retain incomplete directories for inspection and never replace an existing state or backup. Checksums are integrity evidence, not source authentication or execution grants.

Acceptance: encrypted round-trip and tamper/entropy/path/bounds checks; active writer/process rejection; source-byte invariance; history/file/context/nonce identity after restore/reopen; authenticated read-only API; runtime/CLI no spawn even with a fixture configuration; exact clean checkpoint full Go/vet/build and independent review. Physical phone/AT, real provider/OAuth/cloud, Wiii consent, log retention and backup to a different machine remain separate missing-code/environment gates. Build/cache/state/test outputs stay on E; measure C/E free space at end.

Implemented and scoped-tested at application70216c0; see delivery-local-backup-20261012.md and the exact local packet. Raw trailing-dot/space/tilde/dot-segment aliases are rejected before cleaning; destination ancestors are compared by Windows file identity. Backup JSON uses its own2MiB strict parser, preserving ordinary64KiB wire limits. File pinning and stopped-service lock establish cooperating filesystem consistency; hostile same-owner namespace replacement is outside this acceptance.
