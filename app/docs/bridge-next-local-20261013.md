## Wire-v1 authority policy

An affected exposed reply, including nonterminal streamed text or artifacts, keeps its original `replyId`, `requestId`, source-message ID, recipient bot and current status. A matching post-intake durable authority event supplies a strictly newer sequence, with empty text and no artifacts. No adapter wire field, IPC command, receipt identity or ACK semantics is added. Dependency traversal reuses current context/resource/report authority. It recognizes selected file access/revision, source-history access/revision, project/channel revision, plugin policy, continuity revision and a published report's current source/bot fence. An archived source conversation alone preserves historical context under the existing policy; this code does not invent archive revocation.

Unknown invalid authority without a durable matching event returns conflict rather than fabricating a sequence. Local-owner adapter sessions have no history TTL, and account/provider credential expiry is execution authority rather than an adapter-history expiry. This slice adds no GET mutation, synthetic expiry event or automatic regrant. A later file regrant does not restore the old resource revision or resurrect the original derived output.

All clears for an authority event are projected atomically. The reply page is bounded to 512 cumulative rows and 900,000 encoded JSON bytes. Equal-sequence rows sort by stable reply identity. Other sessions receive none of the reply bodies or clear identities.

The routine page scans 200 journal events. If a pending clear lies later, this read-only cumulative projection extends through the furthest required durable clear, within a 4,096-event hard cap. It upserts every intervening session work event under current authority before advancing the cursor; it does not jump over an independent reply. Exact event-200/event-201, later independent updates and restart replay are covered. Root approved this bounded reconciliation policy after the prior 200-only policy reproduced a repeatable event-201 conflict.

Beyond the 4,096-event cap, 512-row limit, byte limit, startup migration budget or an unknown causal authority, the response remains 409. The historical client then hides its full cache while retaining its original cursor. Repeating an unchanged over-limit request cannot recover that projection. An explicit owner repair/newly scoped history state would need a separately implemented acceptance path; this slice does not claim one exists. It does not claim complete Wiii connector lifecycle. Original ACK replay remains valid history without renewed execution authority.

## Legacy cursor repair and startup bounds

An old producer could return an empty page at the revocation event and advance a client that still held the earlier completed reply. The actual upgrade RED retained cached reply sequence 16 and cursor 17: after restart, GET after 17 returned no clear. A cursor alone cannot prove that the old producer emitted a mask.

Writable startup now captures an ephemeral `adapterOpenedSequence` after replay and appends at most 512 missing `adapter.reply_clear_checkpoint` events before returning the Store. A checkpoint uses existing Event fields only: its Work contains only `requestId`; its reserved hash Nonce binds original adapter/work/publication identity, immutable context/resource/plugin pins and the latest matching typed causal event. It contains no text, artifacts, pin bodies or new destination. Replay and commit enforce the exact shape and reject duplicates, wrong targets, changed binding/hash and mixed metadata. Applying it appends the event only, preserving original Work and all command nonce maps. The validated internal event bypasses generic client command nonce collision guards; a valid independent report command may use the same hash without blocking startup.

GET uses the matching checkpoint's real newer sequence for preloaded legacy history. Unknown causes are skipped during recovery and held only at the adapter read. A pre-open invalid output without a checkpoint stays held, including on read-only Open and when a migration batch leaves more than 512 outputs pending. Read-only Open appends nothing. New producer authority events after the opening boundary use ordinary causal projection, so consuming their clear does not brick the next poll. Existing keys make restart idempotent; a later matching authority revision may produce a new empty mask and one current-key repair without restoring an old selected resource pin. Checkpoint disk I/O failure returns unavailable; previously committed checkpoints survive and replay, while unknown authority does not become journal corruption.

The current source/file/plugin mutators commit authority and then call `suspendInvalidContext()`. A live partial reply usually receives a masked Work.suspending event in that second step. That later event is not an atomic guarantee across a crash. Fixtures cover file/plugin/history partial output, read/restart/next poll, and a valid file.access-only commit that deliberately omits the later work suspension. The helper covers all exposed nonempty text/artifacts under invalid current context.

Root also checked public projection composition: the current app treats the noncanonical checkpoint Work as an authority event and resnapshots before replacing any Work; local-sync visibility rejects its empty owner/channel and advances only the frame. The Go invariant test confirms no phantom Work, changed snapshot Work count, raw body or invented pins, and no nonce-map pollution. This current app composition check is distinct from the historical Wiii wire probes.

Authority events are filtered once per read, avoiding a full unrelated Work-event scan for each invalid root. Each root traverses its context/report dependencies against that filtered candidate list. Projection work is capped at 4,096 events, but the initial journal filter, session-work sorting and dependency checks still scale with retained local history. No Store index or other production file is added. The focused many-irrelevant-events fixture records projection cost separately from snapshot copying; it is diagnostic evidence, not a latency SLA or large-history benchmark.
