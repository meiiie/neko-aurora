## Implemented contract

New shared requests use ContextPin5 and a separate PublishedReportPin. A report remains descriptive output in its exact destination, with publication sequence, source/result hash, publisher provenance and only selected output descriptors/UTF-8 excerpts. Source Work is not relabeled as shared history. Versions1-4 retain their historical captures/hashes. IncludeHistory=false remains effective; combined history/report budget is eight pins and8,000 serialized bytes, with at most four files and explicit omissions.

Groups freeze publication pins at creation. Later stages use the same pins and permitted prior-stage results, never a newer publication selected during retry. Intake, claim, file read and completion recheck current source/destination/bot/plugin authority. Recursive history retains the dependency after a summary omits the direct report. Revocation fences fresh work and masks current derived replies/files/exports. Already read bytes cannot be retracted; owner-wide private Work/profile visibility remains the existing single-owner boundary.

ToolPolicyVersion2 adds the separate trusted `report.read_artifact` reader. Historical builtins/defaults remain unchanged. Omitted/disabled selections gain no reader. A genuinely older unverified descriptor with the same reserved ID stays disabled and shadows the reader; catalogVersion2 distinguishes new lifecycle events without rewriting old journals.

Core attests the exact selected artifact through its authenticated `published:<deliveryId>` derived source, retrieved hash/span, scope/access revision, exact typed arguments and seven-field result. Restored tool pairs cannot relabel it as project.read_file. Reads are limited to the admitted UTF-8 prefix, at most4,000 bytes; this is not unrestricted whole-file retrieval. Implicit private conversation/bot revisions0 are valid provenance; destination audience and launched source epoch remain positive.

Store.Snapshot masks stale RuntimeContext and omits frozen report pins from collaboration projections. Internal Get/group records and journal bytes stay intact. HTTP PublicSnapshot already omitted those fields; the independent defect was the internal snapshot contract.

A rejected unpublished-file tool call follows the existing fail-closed manager behavior: authentic Core stops and the task becomes recovery_required/host_rejected, with no returned bytes/effect or automatic retry. This slice does not claim a graceful model continuation after that denial.

## Remaining product code and gates

[Gap matrix](product-gap-matrix-20261011.md) distinguishes missing code from tests: real broker/OAuth/provider, remote principals and per-human/channel membership, device trust/pairing/relay, authenticated commands/tombstones, database/object-store transport and installable phone/PWA/push lifecycle still need implementation. Use default-off independent loopback fixtures before real login/device provisioning; reject body-supplied actors, stale/revoked sessions and altered/replayed payloads before any data or command projection. This is a next dependency, not implemented remote authentication.

Native Tauri/Wiii owner interaction, physical phone/keyboard/safe-area/AT speech, real model quality, external recipient/connector authority and cloud operation remain separate gates. Signed installer/updater, source edit/forget, isolated parsers, richer retrieval and portable/active recovery also remain open. No stack rewrite, extra bots or new service is introduced.
