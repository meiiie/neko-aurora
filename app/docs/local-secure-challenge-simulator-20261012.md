# Task-bound secure challenge simulation

This local simulator is explicitly default off. Enable only with `--local-secure-challenge-simulator`; snapshot then advertises `local_secure_challenge_simulator_v1`. Disabled methods return the existing unsupported status501. Every descriptor/receipt carries `simulatorOnly:true` and `grantsExecution:false`. No runtime tool, provider, vault, OAuth grant or credential consumer uses these records.

`POST /v1/secure-challenges` accepts `{action:"create",requestId,expectedEpoch,attemptId?,accountId?,accountRevision?,destination,purpose:"secure_input_simulation",clientNonce}`. Owner is derived as local-owner. Exact current task/attempt/account/destination and context authority are required. Server binds owner, request, epoch, requirement/context revisions, attempt, account revision/credential generation, destination, fixed simulation purpose and context digest. Its fingerprint contains no proof or credential. A fresh response includes a random 256-bit simulationCode once. A duplicate create returns the original/current descriptor and an empty code; lookup never reproduces a proof.

`POST /v1/secure-challenges/{id}/resolve` accepts `{action:"approve_simulation"|"decline",fingerprint,clientNonce,simulationCode}`. The code is only a synthetic high-entropy hex proof. Matching uses constant-time digest comparison. Process memory holds a digest and a usable flag. Use, observed expiry and clock rollback burn the flag irreversibly. The digest remains private until close so a known code cannot later enter a public event, metadata field or nonce. Close clears that table. No digest or usable flag is serialized. Wrong code/fingerprint/task/attempt/current authority, cancellation, account removal or stale revisions refuse resolution. Expiry is five minutes and equality is expired. Restart never restores proofs; historical pending receipts describe a past request and confer no readiness or authority.

Public snapshot/events and `GET /v1/command-receipts?kind=secure_challenge&clientNonce=...` contain only typed original input and redacted descriptors. Challenge events never contain code, credential, raw context, task reply or secret-reference value. Resolution is one use; exact committed nonce retries may read the public ACK without creating another outcome. Strict typed replay validates binding, timestamps, auxiliary-field exclusion and no-execution flags. Live creation and replay are both bounded to128 descriptors; resolution of an existing descriptor at that limit remains valid. Command receipts are bounded to512.

This validates an offline protocol boundary. No simulator UI or trusted native owner dialog is implemented. The real local account secure-input card uses a separate DPAPI path and is not task consent. Task-bound broker/OAuth/key consumption, real model/provider and cross-device/cloud identity remain separate missing code/acceptance gates. Synthetic approval must never be presented as user consent for an execution grant.

Independent review reproduced three P2 defects at `d5c202e`: a generated code accepted as nonce, creation replay on cancelled/revoked authority, and nonce collision with metadata commands. The original probe is preserved unchanged in `review_l07_challenge_probe_test.go`, SHA-256 `90dbf1a2b998a434ab5b47857eb908917e6bed27a02c89177b6cb98aa638eae1`. The fix rejects known code substrings and casing changes in public event payloads, blocks code echoes through receipt lookup and public account input, requires current running/context authority during creation replay, and fences challenge nonces against existing ledger command tables in both directions. Historical unrelated metadata namespaces remain compatible. `challenge-independent-green-r2` reruns the original probes and adds active/used/expired public-proof guards. This does not claim global secret detection, detection of a forgotten code after restart, or zeroing all Go/JS heap copies.

The unchanged original4 tests/16 leaves independently passed `be808ab`, but a separately authorized probe then reproduced challenge-first reuse through ordinary intake: intake uses `Work.ClientNonce` while the reciprocal event guards inspected only `Event.Nonce`. The supplemental probe is preserved unchanged as `review_l07_intake_nonce_probe_test.go`, SHA256 `ec1e96584f353e6302995392459138c9e1632ce6c0b0aa58b1956eb01017a4af`. Both direct and shared cases now return conflict without adding an event or Work. Commit and replay inspect both nonce fields. A separate bounded creation/replay test retained its genuine RED; it verifies that replay cannot exceed the live128 limit and that a committed resolution reopens correctly at the limit. `challenge-intake-cap-green-r1` records the corrected original/supplemental/lifecycle and cap tests. The first cap harness incorrectly replayed a resolution against state already containing its nonce; that setup failure remains, followed by the corrected single-cause RED and GREEN.
