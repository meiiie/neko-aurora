# Local account save receipts

Connections metadata advertises `account_save_receipts_v1`. Authenticated `GET /v1/account-receipts?clientNonce=...` returns `version:1`, the original nonce, `found` and `used`. The route rejects duplicate or extra query keys. It never writes the catalog or vault.

When the account still has that nonce as its latest save, the response adds `inputFingerprint` and the current public `account`. The fingerprint already exists in the durable account record. It hashes normalized public input `{id,revision,name,provider,endpoint,model,hasSubmittedSecret}` using Go JSON serialization with sorted map keys and HTML escaping. It contains no secret value, secret digest or vault reference. It proves that the public request shape was committed, not which credential bytes were provided, provider readiness or an execution grant. Same-nonce POST retries that include a secret still require the existing Rust sealer match.

The account store retains only the latest fingerprint and nonce for each account. Later edits or removal produce `found:false,used:true` for the older nonce. The client must show a retired receipt and require review. It must not treat the result as permission to repeat the save with a new nonce. `found:false,used:false` means no committed record was found. After an uncertain secret submission, any retry requires explicit re-entry and the original public shape, revision and nonce. Secrets never enter the durable client metadata intent.

Editing uses the existing account ID and exact expected revision. Provider and endpoint remain immutable. A blank secret preserves the existing vault reference and credential generation. A nonblank secret uses the existing DPAPI Rust host path and increments the credential generation. The API reconciles existing task authority after an account mutation. Accounts remain `stored_unverified`; real provider execution is deferred.

Save admission rejects recognized secret patterns in public name, model, endpoint and nonce. A receipt similarly refuses recognized sensitive legacy public metadata. Original secret values are confined to the existing secure-input and sealer path. This pattern screening is bounded and does not claim to detect every possible secret.
