# Local upload receipt lookup

`local_upload_receipts_v1` adds authenticated `GET /v1/upload-receipts?projectId=...&channelId=...&clientNonce=...`. Exactly these three nonempty, single-valued parameters are required; malformed IDs/nonces, repeated/unknown fields and queries above 1,024 bytes reject. Existing local cookie, Host, Origin and no-store boundaries apply.

The version-1 response is `{version:1,found,clientNonce,input?,file?}`. A committed upload returns `input:{projectId,projectRevision,channelId,clientNonce,filename,sha256,bytes}` from the original journal event and `file` as the current public upload descriptor. Neither contains raw bytes, base64 content or excerpts. A missing nonce returns `found:false` without input/file. A nonce already used by another operation or another original project/channel returns conflict. A closed/poisoned store is unavailable.

Lookup never writes a journal event, reads upload bytes, rebinds a project or grants file access. It can reconcile an original accepted upload after project revision or file-access changes; the original input revision remains unchanged while the current descriptor may be revoked. This receipt proves acceptance of the original upload, not current read/model authority. Download and new model intake continue to enforce their existing current authority.

The frontend can persist bounded upload identity metadata before POST. After reload it must look up the original receipt without POST. A matching committed identity retires the pending intent after fresh public state reconciliation. If the receipt is absent, bytes must be obtained again through an explicit same-file selection; filename/length/SHA256 and original project/channel/revision/nonce must match before any retry. Current stale or revoked scope must remain blocked. Do not persist raw upload bytes, excerpts or secrets in browser storage, auto-create a new nonce, or claim that a metadata marker restores missing bytes.
