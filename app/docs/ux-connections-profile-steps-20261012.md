## Chosen implementation

The existing profile flow now shows three steps: source, profile and scope. Discovery does not inspect a profile. Inspection still requires its explicit action; choosing or adjusting a profile never grants execution. Public metadata and an eligible profile move the visual step to scope, while execution approval remains a separate submit.

The desired budget is visible as one compact sentence before approval. Its editor is a native disclosure using the existing input IDs, bounds and exact request body. Invalid values open the disclosure before browser validation focuses the field. A separately labelled active-budget block reads the original validated consent, including its original duration/absolute expiry. Editing a future form cannot change or visually replace an active grant's budget.

Collapsing the profile panel returns keyboard focus to its opener only when the panel held focus, synchronously within the same open owner dialog. It creates no late-ACK focus restoration. `aria-expanded`, a current-step list and `aria-busy` describe the interaction. A 160 ms entrance and a decorative pending ring use the approved light palette. Reduced motion disables both.
