## Observable user journey

An already bound Wiii session can exceed the existing incremental history window. The user sees an understandable reason and an explicit **repair history** action. Repair reads the durable current history for that exact session/scope in bounded pages. It never registers another session, resends a task/group, changes its nonce, replaces a source binding, starts a model or grants access. Old pending input, original accepted receipt identities, draft/navigation and server journal remain preserved.

The current history cache is replaced atomically only after every page and binding validates. An unavailable/revoked result stays hidden or shows metadata explaining that its source is unavailable. Its original durable task/history is not deleted, and revoked content is not restored from an old cache. This is rebuilding a presentation projection, not recreating Core memory or importing another channel's history.

Interrupted repair, storage failure, unavailable capability, changed scope, changed authority or a late response leaves a recoverable visible error and the safe prior intent/receipt metadata. Provisional pages do not leak into the visible transcript. Channel mismatch remains denied; repair does not select a new destination or refresh authority. New typed snapshot/cursor behavior must be capability gated and compatibility tested against actual available Wiii source.

## Contract and ownership

Root approved the repair budget: at most128 rows and900000 encoded JSON bytes per page, at most8192 rows/64MiB cumulative canonical history bytes, and a five-minute repair lifetime. Budget overflow returns an explicit error, without truncating replies or deleting server history. This closes bounded repair rather than claiming unlimited history. The endpoint is capability `local_adapter_history_repair_v1` with read-only `GET /v1/adapters/sessions/{id}/history` and subsequent sole opaque `cursor` query. The cursor binds the frozen journal head, full session/scope, authority witness and whole projection digest. Its signing key is independent server-lifetime randomness, never the authentication cookie. Server restart invalidates unfinished cursors safely. Every page checks current authority, including revoke/regrant changes; the client commits no provisional page. A final zero-row confirmation follows private candidate persistence and precedes the active manifest pointer. Exact wire/canonical digest is frozen; the client storage implementation must satisfy those publication guards.
