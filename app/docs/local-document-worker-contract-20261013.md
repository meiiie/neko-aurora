## Wire and launch

The trusted production main constructs a documentworker Client using its own absolute executable and passes it to `ledger.OpenWithDocumentWorker`. There is no HTTP/journal/file/model/env argument selecting a helper executable or command. No shell or PATH lookup is used. `--document-worker-v1` is accepted only as the sole process argument, before normal flag handling or any Store, state, HTTP, vault, identity, backup, profile or Core setup. Worker stdin carries one request; stdout one result; EOF is required. Child stderr is discarded within a bound. Worker parsers do not fetch relationships, evaluate formulae, run document code or create descendants.

Request: ASCII `NDW1`, one format byte (`1` DOCX, `2` XLSX, `3` PPTX), big-endian uint32 raw length, exact raw bytes, EOF. Response: ASCII `NDR1`, status byte (`0` reject, `1` success), big-endian uint32 UTF-8 text length, 32 raw SHA256 bytes of text, exact UTF-8 text, EOF. A reject has zero length, all-zero digest and no text. Success has nonempty text, exact size/digest and valid UTF-8. Bad magic/version/format/length, short/trailing/multiple frames, invalid text or mismatch is rejected without partial output. No filename/path/state/account/runtime/cookie/grant appears on the wire. A parser error is represented only by the fixed reject shape.

## Bounds and lifecycle

Existing parser policy stays: raw1MiB, ZIP entries256, claimed/actual uncompressed8MiB, per XML/rels part2MiB, XML depth64, complete text512KiB, Office values65,536 and selected parts128. Supervision adds two active workers, immediate busy failure without an unbounded queue, a15-second invocation context/process timeout, stdout4MiB and stderr64KiB. Reap/pipe cleanup has a250ms WaitDelay bound; parent filesystem/hash/temp operations are not a global wall-clock/SLO guarantee. Positive bounded fixture acceptance verifies deadline headroom. Output caps apply while streaming. Failure closes pipes, kills and reaps the owned direct worker, frees its slot and returns a fixed extraction error without diagnostics/source values. Child environment uses only named safe OS variables and private working/temp/profile paths, without inherited credential/profile/runtime settings. Cleanup targets are only the freshly created NewSelf root and its freshly created call directories; incoming format/document bytes do not contain or choose a cleanup/working path.

This is process/deadline/output/concurrency containment. It is not a Windows restricted-token, filesystem/egress sandbox, hard RSS limit, hostile-input fuzz campaign or physical power-loss proof. Pure documents parsers remain independently testable. `ledger.Open` retains the historical direct-parser library/unit path; configured production main uses mandatory nonnil `OpenWithDocumentWorker` and never falls back when the worker fails. A legacy library embedding is not configured-production acceptance.

## Authority and durable behavior

Upload, preview and every pinned tool-read reparse share the Store's immutable extractor. Upload still parses off-lock and rechecks project/channel/archive/quota/dedup under the lock. Preview still captures descriptor, parses off-lock and compares exact current descriptor/project/access. Tool preparation still parses off-lock before the unchanged runtime epoch/context/account/executor/immutable-source checks. Parent rechecks complete extracted text/hash/size and secret screening; parsed bytes are not access authority.

The shared ledger seam independently validates every returned Result, including trusted injected extractors: nonempty valid UTF-8 within the existing512KiB, exact byte count, and a freshly computed full-text SHA256 exactly matching the reported lowercase hash. Error or malformed metadata zeroes the returned Result and remains extraction failure. This identity check is separate from safeExtractedText: a well-formed result containing recognized sensitive/control text still follows the original upload rejection and preview/tool denial policy. Client frame verification alone is not substituted for this parent composition guard.

Busy/timeout/crash/framing failure is extraction failure. Initial Office upload retains original bytes and the existing quarantine policy; it never becomes ready from partial text. Original accepted nonce/receipt/ID/raw hash/status remain authoritative on exact retry, including an acknowledged quarantined upload even if a later worker succeeds. Preview/tool fail closed without journal/ACL/revision/nonce changes. There is no automatic regrant, unquarantine, resume, effect retry, changed extraction version, raised parser quota or Core memory reconstruction.
