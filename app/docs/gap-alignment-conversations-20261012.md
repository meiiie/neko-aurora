## Ba lát cắt local hữu ích tiếp theo

Đây là thứ tự đề xuất theo dependency, không tự mở thêm quyền hoặc thực thi những tác vụ ngoài slice hiện tại.

1. **Bộ bảo toàn và restore dry-run có manifest.** Đóng phần data durability tối thiểu của REQ007/009, §4.12.3/§5.9/SEC54–56: inventory references, detect missing/tampered raw/result/checkpoint bytes, export authorized local data into a revision directory, verify hashes, restore **test data** into isolated E state with scheduling/output disabled. Report incompatible Core/root/install pins rather than editing receipts or restoring grants. Credentials excluded by default; encrypted credential transfer/backup is a separate policy. Acceptance: tamper/missing file, old revoked authority, new stream identity/timeline, original nonce/effect receipt and no blind write after restore. Local rehearsal is not offsite backup, not measured production RPO/RTO.
2. **Bot lifecycle and defaults without permission changes.** REQ003/012, §2.3/§4.5.2: archive/restore bot separate from conversation; show unresolved work instead of silently cancel/delete; keep ID/alias/files/old Work pins. Add model/account default as metadata selection for **new** intake only, exact revision/capability gate and no automatic fallback/secret use. Continue saying stored_unverified; no provider call. Acceptance: archive during old background job, routed fresh intake conflict, restore/restart, pending ACK/draft/current selection, changed/removed default account. Rename, conversation archive and physical deletion remain different commands. Source view of context/“vì sao dùng nguồn này” can accompany the next memory-specific slice, but do not label IncludeHistory as full memory-off.
3. **Task-bound secure challenge/provider boundary with simulator only.** REQ011/012, §3.4/3.5/§6.4/SEC09–24: backend-generated owner/session/task/attempt/account/destination/purpose/expiry/nonce challenge, one-time canary submit, read-only unknown-result lookup, redacted receipt, secret clearing on every dismissal/context change. Add a trusted endpoint registry and redirect/audience/URL boundary using offline/synthetic fixtures before any key consumption. OAuth state/PKCE/callback schema can be validated locally but no actual OAuth flow or grant is initiated. Acceptance: double-submit, late callback, account/destination revision swap, replay/expiry, same secret never in chat/event/localStorage/export/log, no automatic retry of unknown submission. Actual provider/OAuth/key broker/model evaluation stays a separate authorized gate.

File sandbox/PDF extraction, richer scoped memory editing, Project-wide controls, current-attempt renewal and remote sync protocol are also legitimate local code work. They remain listed rather than silently converted to acceptance blockers. Active pause must be a Core/host protocol slice; remote pairing must be a principal/auth/key/revoke design slice. Neither should be implemented as a visual toggle over the current local receipt.
