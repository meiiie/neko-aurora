# Metadata intent reconciliation

Capability `local_metadata_receipts_v1` extends the existing read-only `GET /v1/command-receipts?kind=...&clientNonce=...` route. New kinds: bot_create, bot_name, bot_profile, project_save, conversation_create, conversation_archive. Existing bot_control/project_control remain available. No new POST/regrant/secret endpoint is introduced.

Every found receipt returns the original typed normalized input plus current corresponding metadata (`bot`, `botProfile`, `project`, or `conversation`). Original name/profile/project/conversation revision and nonce remain fixed after later metadata changes or restart. Unknown kind is invalid; a nonce belonging to a different known kind conflicts. Current metadata is presentation, not permission to rebind the original intent. No Work/context/runtime/account credential/file bytes are projected.

bot_create input equals normalized BotInput. bot_name adds path-derived botId to BotNameInput; bot_profile adds botId to BotProfileInput. project_save returns original ProjectInput: id is empty for a creation and the project ID for an update. conversation_create equals ConversationCreateInput; conversation_archive adds path-derived conversationId to ConversationArchiveInput. Empty defaults fields on bot_control may be omitted in JSON; canonical typed comparison restores only known zero fields, without accepting unknown fields or changing revision/body.

UI must persist a bounded exact kind/route/body/nonce/revision/hash intent before first POST. On reload it performs receipt lookup/resnapshot only. Found receipts retire the original intent after identity verification. Unknown receipts permit an explicit same-body retry while current scope/revision and a short intent TTL remain valid; stale/expired/revoked or clock-backward intents require review, with no automatic new nonce or POST. Storage failure blocks the first mutation. The journal contains only authorized metadata text and IDs; reject recognized sensitive text and never persist account secrets, raw Work/context, raw files or credential values. Existing legacy journal replay and historical namespace semantics remain compatible.
