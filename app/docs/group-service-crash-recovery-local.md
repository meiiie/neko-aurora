# Explicit finite-group service-crash recovery

Base: immutable Root `022a06a17966b7665d9d41658ffba8bc9a0aab46`. This additive backend protocol reuses the trusted native stop-outbox and existing Core context-v1 resume. It does not restart a new group or run another agent loop.

`POST /v1/collaborations/{id}/recover` requires the existing local-owner session/origin. Exact input:

```json
{"version":2,"requestId":"req-<32 lowercase hex>","expectedRevision":4,"expectedEpoch":2,"expectedTaskRevision":0,"clientNonce":"original-owner-command-nonce"}
```

All three CAS counters must be present. `expectedRevision` is the group revision; the other two are the exact current stage counters. Unknown/duplicate keys, caller proof/path/PID, wrong versions and malformed input return 400. Unsafe/stale proof or authority returns 409 without recovery intent. A valid current-scope request observing time outside the original budget may separately record its irreversible time observation; it never commits recovery/work changes. Success is 200 `{collaboration,work,duplicate}`. Capability `local_collaboration_service_recovery_v1` appears only with a configured executor and required context-v1 admission.

Only the last exactly mapped stage may recover. Group must be `suspended` with `task_suspended`, task `suspended`/desired `suspended` with `executor_lease_unavailable`. The saved current attempt must have original install/lease, exact Core/current attempt binding and context-v1 admission, positive FILETIME generation and valid actual stopped receipt. Started/unknown effects deny. Earlier stages must remain completed, nonempty, effects resolved, native-stopped and authorized. Missing/old-generation/context-v0 evidence stays blocked.

The original goal, participants, stage nonce, request/message IDs, stage list/order, maximum three stages, created time, five-minute deadline, account/plugin/install/project/source pins, context/session/manifest, output and effects remain unchanged. Recovery atomically writes `collaboration.recovered` containing both restored group intent and the same current work. It increments group revision, task revision and task epoch; no stage is added. A later normal claim acquires a new attempt/lease/fence with the original Core receipt, never renews the old lease.

Original current and ancestor source access, plugin, channel audience, project/source, account and exact install authority are checked. The recovery check ignores only the stopped group's status for its exactly mapped original stages; it does not authorize other groups, orphan work or revoked sources. Group creation/deadline remain the finite ceiling. Backward clock and expiry deny; live claim, prompt, admission, output, tool dispatch/effect and completion are additionally fenced at that ceiling, even between manager ticks. Replay checks the recorded UTC `issuedAt` against the saved finite budget and original typed history, never today's clock or registry. Live and replay share the original saved account lease window (`issuedAt <= recovery time < expiresAt`) and deny an irreversible `AccountExpiredAt` marker even after a clock rewind; recovery never renews or replaces that original account lease.

The journal transition is guarded under ledger -> account -> executor locks. Callback performs only the commit. NEW create/recover/cancel/task-control intake nonces cannot be rebound across these four command kinds. Each matching committed receipt is checked first, so genuine historical overlaps still return their original success. Repeated exact recovery nonce returns current original group/stage receipt even after later cancellation; it never revives anything. Changed input conflicts. Already committed legacy task/cancel/create/recovery receipts retain idempotent retries even if historical independent nonce indexes overlapped; new intake cannot create such overlap. New recovery journal events carry internal `nonceDomainVersion:1`, which validates all known command indexes during replay. Omitted version 0 preserves genuinely accepted old recovery history, including the old create/recovery overlap; unknown versions deny. This discriminator is never caller HTTP input or part of the original command-receipt input body. Existing historical create/task/cancel replay schemas remain unchanged; global nonce uniqueness is a new-intake guarantee, not a claim about legacy journals. Recovery actions are bounded to 2048 stored collaboration actions.

Read-only lookup: `/v1/command-receipts?kind=collaboration_recover&clientNonce=<nonce>&collaborationId=<exact group ID>`. It returns version-1 command receipt, original V2 input, current same group and same stage work. Private context manifests/pins/archives and file excerpts are stripped. Wrong command kind/group conflicts; a known nonce that has no receipt of the requested valid kind conflicts rather than appearing missing. A successful original receipt is returned first, preserving historically overlapping command indexes. Only a nonce absent from all command indexes returns found:false. Reload must not POST automatically: only an explicit retry may resend the exact original nonce and CAS.

Task controls still reject collaboration-bound stages. This slice does not add group pause, goal replacement, regrant, deadline renewal, missing-proof adoption or automatic resume. Explicit group cancellation retains effects and original native proof. Native proof production and bounded periodic late-outbox reconciliation are unchanged. A suspended exact current context-v1/generation attempt awaiting the service-crash stop fact remains suspended intent through repeated group-manager ticks; it is not converted into owner cancellation. An explicit group cancel remains fenced and waits for a valid actual stopped receipt before settling its pending cancelled stage. Missing/corrupt proof never settles cancellation or permits recovery.

Validation is recorded against exact clean commits. Typed synthetic ledger/API tests and compiled Go/Rust/Core loopback fixtures are distinguished from actual provider/model quality, cloud sync, GUI or physical phone acceptance. Failed baseline API route test is retained separately; no previous receipt packet is overwritten.

The manager records an irreversible `collaboration.budget_closed` fact when it observes an active group's time at/after the original deadline or before its creation time. Public `budgetClosedAt` and `budgetClosedReason` metadata preserve that observation through restart and clock rewind; a closed budget always denies a fresh recovery/claim/output/effect. Its strictly canonical recorded timestamp is replayed against the original five-minute interval, never today's clock. A suspended group awaiting a late native stopped receipt keeps its status, intent, stage/proof/effects and original budget; observing expiry neither fabricates a stopped fact nor turns that waiting stage into automatic cancellation. Explicit cancellation can still wait for and settle an authentic late receipt. Historical journals omit these additive fields and remain readable. A failed recover remains a 409 without recovery intent. A valid current-stage CAS request, normal live stage claim/prompt/output/effect/completion guard, or manager tick observing invalid budget time records only the separate budget closure fact, not the denied operation; stale/mismatched requests do not write that observation. Matching successful duplicate receipts resolve first and do not observe/renew budget. UI must hide recovery when `budgetClosedAt` is present even if its local clock is inside the saved interval.
