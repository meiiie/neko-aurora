# Local bot state and requested defaults, version 1

`local_bot_states_v1` and `local_bot_default_intake_cas_v1` describe the local journal and intake contract. Snapshot retains every bot, history, account reference and old task, and adds `botStates`: `{version:1,botId,revision,archived,defaultAccountId?,defaultAccountRevision?,defaultModel?}`. An unchanged bot has revision0. Archive changes no source permissions, account leases, channel membership or running obligation.

`POST /v1/bots/{botId}/state` accepts `action:archive|restore|defaults`, required `expectedRevision` and `clientNonce`. The defaults action requires all three default fields, including empty account ID/revision0 for no account. Archive/restore reject default fields. Responses are `{botState,duplicate}`. Exact original retries return current metadata before live catalog checks; a changed input with the same nonce conflicts. Default account must match the current exact catalog revision and catalog model. This metadata is a requested preference, never proof of connected provider/model or an execution grant.

`GET /v1/command-receipts?kind=bot_control&clientNonce=...` is read only. The result contains version, kind, found, nonce, and when found the original typed input (including path-derived botId) and current botState. No Work or credential is returned.

New message intake may use `useBotDefaults:true` plus the required `expectedBotStateRevision`, resolved against the receiving bot after a leading `@alias`. Account fields must be absent/empty for this mode. A successful Work pins `useBotDefaults`, `expectedBotStateRevision`, and `botStatePin`, alongside its exact account pin if present. A stale bot revision/account conflicts without fallback. Explicit manual account or no-account mode remains available. Mode/revision/body/nonce stay frozen through uncertain retry; original ACK lookup precedes current defaults and account checks.

Fresh direct/routed/group intake rejects archived bots. Old tasks, typed linked controls and finite group stages preserve acknowledged obligations. Linked controls inherit the parent's default preference pin; new groups retain their existing explicit shared account contract. No per-stage live default selection is introduced. Replays validate typed state events, intake pins and lineage. Snapshot/events/receipts return independent copies.

The fixture Core runtime still uses its existing model configuration. Desired model metadata does not switch a real provider. No cloud, physical phone, native owner dialog or real model acceptance is inferred from local API/ledger tests.
