## User flow

The work drawer shows “Phục hồi bước hiện tại” on the group card, not an individual stage control. It shows the remaining original five-minute budget and three-stage limit. Recovery preserves the group, mapped request, original Core session/context, selected account/resources and original deadline. It does not create a replacement stage, renew a budget, regrant access or refresh context. Default intake and the approved composer/palette remain unchanged.

The action is capability-gated by `local_collaboration_service_recovery_v1`, `local_command_receipts_v1` and `local_collaboration_v1`. Observable eligibility requires suspended/task_suspended, the exact last mapped stage with suspended/suspended/executor_lease_unavailable, current typed native PID/generation/session/attempt/install/context admission and stopped receipt, completed effects, current original authority, an unexpired original account lease window and live original group budget. Prior mapped stages must be completed, nonempty, stopped and effects-complete. Account lease metadata is a local fixture descriptor; UI does not treat it as a grant. The additive `budgetClosedAt`/`budgetClosedReason` lifecycle fact makes eligibility false regardless a later clock rewind. Observed closure cannot be cleared or rewritten by a later ACK; it does not alter original immutable goal/resources/deadline. Receipt retirement remains read-only and valid after closure. The server remains the final authority.

## Durable command

POST `/v1/collaborations/{id}/recover` carries exactly version 2, requestId, expectedRevision(group), expectedEpoch(stage), expectedTaskRevision(stage) and clientNonce. The existing bounded Web Locks command journal stores only this canonical input and public original scope metadata. No Core manifest, context, excerpt, lease proof, secret, upload bytes or provider credential is persisted.

Reload reads `/v1/command-receipts?kind=collaboration_recover&clientNonce=...&collaborationId=...` and a current authenticated snapshot. It never automatically POSTs. A valid committed receipt must preserve the original typed input, same group and original mapped stage, scopes and minimum post-command counters. Reconciliation retires the intent using read-only calls even when current counters now prohibit retry. An absent receipt permits only an explicit retry with the original body/nonce/CAS and still-valid authority/budget; stale scope or counters fail closed. Pending commands retain a visible “Đối soát lệnh gốc” action rather than mint a new nonce. After a validated typed GET proves the recovery nonce absent, the owner may explicitly Cancel the group with its current separate CAS/nonce; the original recovery record remains read-only. Unknown/error responses never authorize this path. Beginning another recover POST or another lookup invalidates the old absence observation.

An atomic collaboration.recovered SSE contains both group and work. UI applies both only when neither observed counter regresses. Late HTTP ACK cannot replace newer cancellation, change navigation, overwrite a draft or steal focus. Before pending disable, proof/budget loss or SSE hiding, a focused group recovery control moves synchronously to Close inside the mobile work dialog. It has no asynchronous ACK focus restore.
