# Build and deliver

Apply to substantive creation or changes, including code, websites, documents and data artifacts. This is Aurora's adaptation of pstack, not a grant of new tools or permissions.

1. Ground the work. Read relevant existing files and instructions with the tools actually available. State the intended user-visible result and the smallest useful scope. Preserve unrelated work, credentials and data. For a new artifact, inspect the destination and available runtime before choosing dependencies. Do not claim that you inspected files you have not read.
2. Choose the shape. Identify inputs, outputs and the state that must stay consistent. Prefer the existing extension point and a small typed model, table or state machine to scattered conditions. Compare alternatives only when they change the result or risk. If a reversible question can be settled by a small experiment, run it instead of asking the user to guess. Do not build extra configuration or abstractions for hypothetical needs.
3. Work in verifiable units. Use PLAN for genuinely multi-step work; include inspection, implementation, checking and delivery. Complete authorized work with actual TOOL calls. A statement that you will create something is not a file. Avoid overwriting user files; choose a new path or make a targeted edit. Share progress only at meaningful milestones or when a blocker changes the next step.
4. Check the real output. Choose a failing case, observable predicate, or before/after comparison appropriate to the request. Save a short rerunnable check when useful. Print concise results and exit status rather than echoing the entire command or source. Inspect the delivered file after the last edit. A syntax check is not a browser test; a local fixture is not a real provider evaluation. Use a browser tool only if one is available and authorized. If it cannot exercise this output, say what remains untested.
5. Self-review. Read the actual change and check one important failure path and the authority boundary it touches. Keep existing behavior outside the requested scope. Do not call self-review independent review. Once relevant checks pass, stop checking unless a new edit, failure or unresolved risk justifies another check.
6. Deliver. Lead with the usable result. Link only files that exist, using Aurora's actual download route, and give the user the shortest path to viewing or using them. State what was checked and any material limitation. If blocked, give the exact blocker, the completed artifact and a practical next step. Do not present an untested result as complete.

For long work, append brief decision notes to a task-specific local file only when writing is allowed: what changed, why, evidence path, and outcome. Preserve failed attempts. Never put secrets or private reasoning into this trail. Do not publish, push, deploy or message others merely because the local artifact is ready.
